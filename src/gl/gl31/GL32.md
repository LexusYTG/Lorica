# Lorica GL31 - soporte de OpenGL 3.0 / 3.1 / 3.2

Esta capa traduce GL de escritorio (hasta 3.2 core) a un backend GLES 3.0, 3.1 o 3.2.
La version anunciada por `glGetString(GL_VERSION)` es **3.2** si el backend tiene geometry
shaders (ES 3.2 o EXT/OES_geometry_shader) y **3.1** si no. GLSL anunciado: 1.50 / 1.40.

## Que backend da que

| Funcion de GL | ES 3.0 | ES 3.1 | ES 3.2 / extensiones |
|---|---|---|---|
| Sync objects, queries 64 bit, samplers (todos los `glSamplerParameter*`) | nativo | nativo | nativo |
| `glDrawElements*BaseVertex` | emulado (desplaza punteros de atributos) | emulado | nativo (ES 3.2 / EXT_draw_elements_base_vertex) |
| `glProvokingVertex` | solo LAST | solo LAST | FIRST con EXT/ANGLE_provoking_vertex |
| Texturas 1D, 1D array, RECTANGLE | emuladas como 2D / 2D array | igual | igual |
| Texturas multisample 2D, `glSampleMaski`, `glGetMultisamplefv` | no (error + aviso) | nativo | nativo |
| Multisample 2D array | no | solo con OES_texture_storage_multisample_2d_array | nativo |
| `glTexBuffer`, `samplerBuffer` | no | con EXT/OES_texture_buffer | nativo |
| Geometry shaders, primitivas con adyacencia, `glFramebufferTexture` | no | con EXT/OES_geometry_shader | nativo |
| `gl_ClipDistance` | no | con EXT_clip_cull_distance | igual |
| `glBindFragDataLocation` | emulado (relink con `layout(location)`) | igual | igual |
| `glGetTexImage` | emulado con FBO + `glReadPixels` (solo formatos renderizables) | igual | igual |
| Subida `GL_BGRA` + `UNSIGNED_BYTE` | emulada (intercambio R/B en CPU) | igual | igual |

## Conversor GLSL (gl31_shader_glsl.c)

* Version de salida segun el backend: `#version 300/310/320 es`.
* `sampler1D`, `sampler1DArray`, `sampler2DRect` (y variantes `i`/`u`) pasan a `sampler2D` /
  `sampler2DArray`. Las llamadas `texture`, `textureLod`, `texelFetch`, `textureSize` sobre ellos se
  redirigen a funciones `lorica_*` inyectadas (coordenada extra 0.5; en Rect `p / textureSize`).
  Se detectan por el nombre con que se declaro el sampler (incluye parametros de funciones).
* `glGetActiveUniform` informa el tipo de desktop (`GL_SAMPLER_1D`...) de esos uniforms.
* Se inyectan los `#extension` EXT/OES que el backend exige por debajo de ES 3.2.
* `glBindFragDataLocation` guarda el pedido y, al linkear, reconvierte los fragment shaders
  agregando `layout(location = N)`.

## Limitaciones conocidas (honestas)

* **Nada de esto se probo sobre una GPU Mali real ni con EGL.** Las pruebas usan un backend
  simulado (`tests/`): verifican la logica de traduccion, no el comportamiento del driver.
* La integracion con GL4ES no esta en este paquete.
* Sobre sampler 1D / Rect no se admiten `textureProj*`, `textureGrad`, `textureOffset`,
  `textureGather`, ni sombras 1D / Rect (error de compilacion con mensaje claro). `textureLod` sobre
  Rect no existe en GL.
* Los helpers de sampler solo se aplican cuando el sampler se declara en el mismo shader; un sampler
  1D pasado a una funcion de otro shader no se detecta.
* Texturas multisample: el almacenamiento de ES es inmutable; volver a llamar
  `glTexImage2DMultisample` sobre la misma textura da `GL_INVALID_OPERATION` (en GL escritorio seria legal).
* `glGetTexImage`: no soporta texturas comprimidas, depth/stencil ni formatos no renderizables en ES.
  `glGetCompressedTexImage` siempre da `GL_INVALID_OPERATION`.
* `glFramebufferTexture` sin geometry shaders adjunta solo la capa 0 (con aviso).
* `GL_BGRA` en subidas solo con `GL_UNSIGNED_BYTE` / `UNSIGNED_INT_8_8_8_8_REV` y sin PBO de desempaquetado.
* `glPolygonMode` LINE/POINT, `glClampColor`, `GL_UNPACK_SWAP_BYTES` y `LSB_FIRST` siguen siendo avisos sin efecto.
* Base vertex emulado: modifica y restaura los punteros de atributos en cada draw (costo extra en CPU);
  solo cubre atributos con buffer y sin divisor.
* Geometry shaders: el conversor solo ajusta version/extensiones/layouts; las diferencias de semantica
  entre GS de escritorio y ES (limites de salida, bloques de interfaz) las valida el compilador del driver.
* `GL_DEPTH_CLAMP`, `GL_TEXTURE_CUBE_MAP_SEAMLESS` y `GL_CLIP_DISTANCEi` en `glEnable` se guardan como estado
  "blando" (se pueden consultar) pero no se reenvian al backend.
* El estado se comparte entre contextos para shaders / programas / texturas / VAOs y no tiene locking.

## Pruebas

`make test` compila y corre tres ejecutables: `test_uniform`, `test_integration` (v1) y `test_gl32`
(sync, base vertex, texturas 1D / multisample / BGRA, conversor GLSL, frag-data, dispatch table).
Verificado con gcc y clang (`-Wall -Wextra`, sin avisos) y con AddressSanitizer + UndefinedBehaviorSanitizer (gcc).
