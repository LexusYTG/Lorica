# Lorica GL31 - OpenGL 3.3 (y cierre de 3.0-3.2)

Con geometry shaders en el backend (ES 3.2 o EXT/OES_geometry_shader) se anuncia **3.3 / GLSL 3.30**.
Sin ellos se anuncia 3.1. `gl31_set_max_version(3, 2)` o `LORICA_GL_MAX_VERSION=3.2` fuerzan 3.2.

## Lo agregado para 3.3

| Funcionalidad | Como se resuelve |
|---|---|
| `ARB_timer_query`: `glQueryCounter`, `GL_TIMESTAMP`, `GL_TIME_ELAPSED`, `glGetQueryObject[u]i64v` | nativo con `EXT_disjoint_timer_query` (64 bit). Sin ella: resultado 0, query "siempre disponible" y un aviso |
| `ARB_blend_func_extended`: `glBindFragDataLocationIndexed`, `glGetFragDataIndex`, `GL_SRC1_*`, `layout(index = 1)` | nativo con `EXT_blend_func_extended` (se agrega el `#extension` solo si el shader usa `index`). Sin ella: `GL_INVALID_OPERATION` con aviso y el `layout(index)` se descarta |
| `ARB_vertex_type_2_10_10_10_rev`: `glVertexAttribP{1..4}ui[v]` | desempaquetado en CPU hacia `glVertexAttrib4f` (con/sin normalizar, con/sin signo). Los punteros de atributo 2_10_10_10 ya iban nativos |
| `ARB_texture_swizzle`: `GL_TEXTURE_SWIZZLE_RGBA` | se expande a los cuatro `SWIZZLE_R/G/B/A` de ES (set y get) |
| `ARB_explicit_attrib_location`, `ARB_occlusion_query2`, `ARB_texture_rgb10_a2ui`, `ARB_shader_bit_encoding`, `ARB_instanced_arrays`, `ARB_sampler_objects` | ya vienen en ES 3.0; solo se anuncian |
| `glBeginQueryIndexed`, `glEndQueryIndexed`, `glGetQueryIndexediv` (4.0) | solo indice 0 |

Ademas: los ids de queries "falsas" y las queries activas ahora se reinician en `gl31_init` / `gl31_shutdown`.

## Limitaciones

* `GL_MAX_DUAL_SOURCE_DRAW_BUFFERS` es 1.
* Compresion RGTC (BC4/BC5, parte de 3.0) y S3TC solo si el backend las ofrece; no se transcodifican.
* Las funciones de compatibilidad (`glVertexP*ui`, `glColorP*ui`, `glTexCoordP*ui`...) no existen en core y no se publican.
* **Nada se probo sobre una GPU Mali real**; los tests usan un backend simulado (ASan/UBSan, gcc y clang sin warnings).
